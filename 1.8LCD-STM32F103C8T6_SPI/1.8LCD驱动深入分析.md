# 1.8 寸 LCD(ST7735S) 驱动深入分析

## 1. 资料范围与结论
本分析基于该工程中的主程序、驱动层和编译产物，核心结论如下：

- 控制器为 ST7735S，SPI 接口，分辨率 128x160（竖屏）或 160x128（横屏）。
- 驱动采用 GPIO 模拟 SPI（非硬件 SPI 外设）。
- 像素格式使用 RGB565（16bit），即命令 0x3A 配置为 0x05。
- 显存窗口写入采用列/行偏移补偿（+1/+2），适配了具体面板玻璃偏移。

关键依据文件：

- USER/main.c
- HARDWARE/LCD/lcd_init.h
- HARDWARE/LCD/lcd_init.c
- HARDWARE/LCD/lcd.c
- OBJ/LCD.htm

## 2. 驱动分层与调用链
### 2.1 逻辑分层
- 应用层：main 中调用显示 API 进行文本、数字、图片循环显示。
- 图形层：lcd.c 提供点、线、矩形、圆、字符、中文、图片显示。
- 传输层：lcd_init.c 提供命令/数据发送、地址窗口设置、初始化序列。
- 硬件抽象层：lcd_init.h 通过宏直接控制 GPIOA 引脚。

### 2.2 启动调用链
- main -> LCD_Init -> LCD_GPIO_Init -> GPIO 初始化
- main -> LCD_Fill / LCD_ShowChinese / LCD_ShowString / LCD_ShowPicture
- 图形 API 最终下钻至 LCD_Address_Set + LCD_WR_DATA

OBJ/LCD.htm 中也能看到同样的调用关系与栈深度统计，说明源码与构建结果一致。

## 3. 硬件接口与引脚占用
在 lcd_init.h 中定义如下：

- PA0: SCLK
- PA1: MOSI
- PA2: RES
- PA3: DC
- PA4: CS
- PA5: BLK(背光)

特点：

- 单向写总线（没有读回引脚），适合低成本显示。
- 所有时序由软件控制，移植简单但性能受 CPU 主频和编译优化影响。

## 4. 初始化序列拆解(ST7735S)
初始化位于 lcd_init.c 的 LCD_Init，主要步骤：

1. GPIO 初始化
2. 硬件复位（RES 拉低/拉高，含延时）
3. 开背光
4. Sleep Out: 0x11，延时 120ms
5. 帧率相关：0xB1/0xB2/0xB3
6. 反相设置：0xB4
7. 电源/VCOM：0xC0~0xC5
8. 内存访问方向：0x36（依赖 USE_HORIZONTAL）
9. Gamma：0xE0/0xE1
10. 像素格式：0x3A=0x05（RGB565）
11. Display On：0x29

这是一套典型 ST7735S 上电序列，且与 128x160 小尺寸彩屏常见参数基本一致。

## 5. 坐标系、方向与偏移机制
### 5.1 方向控制
USE_HORIZONTAL 支持 0/1/2/3 四种方向，并在 0x36(MADCTL) 中选择不同参数：

- 0 -> 0x00
- 1 -> 0xC0
- 2 -> 0x70
- 3 -> 0xA0

当前默认 USE_HORIZONTAL=1。

### 5.2 分辨率宏
- USE_HORIZONTAL 为 0/1 时：LCD_W=128, LCD_H=160
- USE_HORIZONTAL 为 2/3 时：LCD_W=160, LCD_H=128

### 5.3 地址偏移补偿
LCD_Address_Set 对 x/y 增加固定偏移（+1 或 +2），这是 ST7735 模组非常常见的“玻璃对齐补偿”。

工程中的偏移配置已经与当前屏匹配；若更换同为 ST7735 的不同模组，这里最可能需要调整。

## 6. 数据通路与显示 API 行为
### 6.1 总线发送
- LCD_WR_REG: 发送 8bit 命令
- LCD_WR_DATA8: 发送 8bit 数据
- LCD_WR_DATA: 发送 16bit 数据（高字节在前）

这与 RGB565 像素格式一致。

### 6.2 图形接口
lcd.c 提供：

- 基础绘制：LCD_DrawPoint / LCD_DrawLine / LCD_DrawRectangle / Draw_Circle
- 区域填充：LCD_Fill
- 文本显示：ASCII + 中文点阵
- 图片显示：LCD_ShowPicture

main.c 中连续调用这些接口，可作为回归测试样例。

## 7. 性能与资源评估
### 7.1 全屏刷写数据量
RGB565 全屏数据量：

- 128x160x2 = 40960 字节

### 7.2 模拟 SPI 的开销
当前每个字节通过软件循环位移发送，且每字节都拉低/拉高 CS。特点：

- 优点：实现简单，几乎无外设依赖。
- 缺点：吞吐较低，刷新率受限；CPU 占用高。

在复杂动态界面中，这会成为首要瓶颈。

## 8. 已识别风险点
- 编码风险：注释与中文字符串存在乱码现象，跨平台编辑可能导致文本进一步损坏。
- 兼容风险：地址偏移与 MADCTL 强绑定当前面板，更换屏后可能出现边缘错位或镜像。
- 性能风险：bit-bang SPI 对全屏动画不友好。

## 9. 移植与优化建议
### 9.1 最小改动移植到其他 STM32
- 保留 lcd.c 与大部分 lcd_init.c。
- 只改 lcd_init.h 的引脚宏与 GPIO 使能端口。
- 校准 LCD_Address_Set 偏移与 0x36 参数。

### 9.2 中等改动优化
- 将模拟 SPI 替换为硬件 SPI。
- 合并连续像素写入，减少函数调用开销。
- 在整屏填充/贴图路径中减少重复地址窗口设置。

### 9.3 高性能方向
- 使用 DMA + SPI 批量传输。
- 构建脏矩形刷新机制，避免全屏重复刷。

## 10. 快速核对清单
- 上电黑屏：先查 RES/BLK 时序与 0x11 后延时。
- 颜色异常：核对 0x3A 是否为 0x05，以及 RGB/BGR 顺序。
- 画面偏移：调整 LCD_Address_Set 的 +1/+2。
- 横竖屏错乱：核对 USE_HORIZONTAL 与 0x36 参数匹配。

本工程作为 ST7735S 入门与二次开发模板质量较高，结构清晰、功能完整。若后续目标是提高帧率，建议优先将模拟 SPI 升级为硬件 SPI + DMA。
