# 2.0 寸 TFT(ST7789 系列) 驱动与初始化资料深入分析

## 1. 资料范围与总体判断
本目录包含三类关键资料：

- 面板初始化文本 1：2.0 寸初始化HSD+ST7789V-2018-12-06.txt
- 面板初始化文本 2：ST7789P3+BOE2.0IPS(B3 GV020QVQ-N81-DQP0)-2.2Gamma-20230515.txt
- STM32 参考驱动：03-参考代码/参考代码/STM32/2.0TFTspi.C

总体判断：

- 参考代码基于 STM32F103，GPIO 模拟 SPI 驱动 ST7789V2。
- 代码默认 240x320，像素格式配置为 18bit(RGB666，0x3A=0x66)。
- 两份文本初始化表更偏向 16bit(RGB565，0x3A=0x05) 的量产参数模板。
- 同名控制器的不同面板组合（HSD、BOE）在 Gamma、Gate、VCOM 等参数上差异明显，不能直接混用。

## 2. 参考代码架构分析
### 2.1 引脚定义
2.0TFTspi.C 中定义：

- PB5: SCK
- PB6: SDA(MOSI)
- PB7: RST
- PB8: DC
- PB9: CS

通过寄存器 BRR/BSRR 直接拉高拉低，形成 bit-bang SPI。

### 2.2 软件结构
- 系统初始化：SYS_init（时钟/PLL）
- GPIO 初始化：IO_init
- 延时：delay_us / delay_ms
- SPI 字节发送：SPI_SendByte
- 命令/数据封装：TFT_SEND_CMD / TFT_SEND_DATA
- 显示接口：OLED_init / OLED_clear / OLED_full / Picture_display / display_char16_16

虽然函数名叫 OLED_xxx，本质是 TFT 彩屏驱动。

### 2.3 主流程
main 的演示流程：

1. SYS_init + IO_init
2. OLED_init
3. 全屏红/绿/蓝测试
4. 清屏
5. 循环显示 100x100 图片与 16x16 汉字

这条路径可视为上电验证、色彩验证、字库验证三合一 demo。

## 3. 初始化序列深度拆解
### 3.1 参考代码中的序列(ST7789V2)
OLED_init 关键点：

- 复位后发送 0x11(Sleep Out)
- 设置窗口 0x2A/0x2B（列 0..239，行 0x28..0x117）
- Porch: 0xB2
- Gate: 0xB7=0x56
- 电源链路: 0xBB/0xC0/0xC2/0xC3/0xC4/0xC6/0xD0
- Gamma: 0xE0/0xE1
- MADCTL: 0x36=0x00
- Pixel Format: 0x3A=0x66（262K，RGB666）
- 0x21(反相开), 0x29(显示开), 0x2C(开始写显存)

### 3.2 两份文本初始化表的共同点
两份 txt 均有：

- Reset + 0x11 + 延时
- 0x36 方向控制
- 0x3A 像素格式
- 0xB2/0xB7/0xBB/0xC0/0xC2/0xC3/0xC6/0xD0
- 0xE0/0xE1 Gamma
- 0x29 + 0x2C

说明它们都属于 ST7789 家族初始化范式。

### 3.3 关键差异点
最重要差异在以下几项：

- 像素格式：参考代码为 0x66(18bit)；两份 txt 为 0x05(16bit)
- Gate/VCOM/Gamma 参数不同
- 有的表包含 0x35(TE) 与 0xD6，参考代码未完整对齐
- 参考代码有行地址起始偏移 0x28

结论：

- 这些参数强依赖具体屏厂与玻璃设计，不能“拼接抄表”。
- 必须按当前实物模组选择一整套匹配参数。

## 4. 数据格式与显存写入模型
### 4.1 18bit 路径
参考代码在清屏/填充/贴图时按每像素 3 字节发送：

- R(8bit) + G(8bit) + B(8bit)

配合 0x3A=0x66，符合 RGB666 模式。

### 4.2 16bit 路径
若改为 0x3A=0x05，数据应改为每像素 2 字节 RGB565。当前代码若只改命令不改发数，会导致颜色错乱和画面异常。

## 5. 性能与工程化评估
### 5.1 刷屏带宽估算
- 240x320 全屏像素：76800
- 18bit 数据量：230400 字节/帧
- 16bit 数据量：153600 字节/帧

对 bit-bang SPI 而言，这一数据量很大，动画性能会受明显限制。

### 5.2 当前实现优缺点
优点：

- 纯寄存器+软件 SPI，移植门槛低。
- 代码直观，适合快速验证面板参数。

缺点：

- 吞吐低，CPU 占用高。
- delay_ms 为空转延时，不同主频下精度和一致性差。
- 代码中图片数组和字库直接内嵌，维护成本高。

## 6. 风险点与排障方向
### 6.1 高风险项
- 参数错配：错误的 gamma/VCOM/gate 可能导致偏色、闪烁、亮度异常。
- 色深错配：0x3A 与像素发送字节数不一致会直接花屏。
- 窗口偏移：0x2B 起始 0x28 不匹配时会出现上下裁切或错位。

### 6.2 推荐排障顺序
1. 确认控制器与面板组合（HSD/BOE/其他）。
2. 固定一套完整初始化表，避免混搭。
3. 验证 0x3A 与像素发送格式一致。
4. 用纯色填充验证通道顺序与方向。
5. 再验证图片和字库显示。

## 7. 落地改造建议
### 7.1 方案 A：继续 18bit
- 保持 0x3A=0x66。
- 保持每像素 3 字节发送。
- 优先上硬件 SPI + DMA 把吞吐做上去。

### 7.2 方案 B：切换 16bit
- 改 0x3A=0x05。
- 所有像素发送函数统一改为 RGB565 两字节。
- 图片资源改为 565 取模，字库颜色也按 565 组包。

### 7.3 建议的工程重构
- 把初始化表抽成 const command table，支持按面板型号切换。
- 统一命名（TFT 而非 OLED），降低维护歧义。
- 将时序层/面板层/图形层拆分为独立文件。

## 8. 与 1.8 寸工程的关键差别
- 控制器代际不同：ST7735S vs ST7789 系列。
- 分辨率不同：128x160 vs 240x320。
- 默认色深不同：565(16bit) vs 666(18bit)。
- 2.0 寸资料中“同控制器多参数版本”问题更突出。

---
结论：2.0 寸资料可直接用于点亮和验证，但若用于产品化，首要任务是统一面板参数版本并明确像素格式策略；随后应尽快升级为硬件 SPI/DMA 架构，以避免 bit-bang 在 240x320 分辨率下成为性能瓶颈。
